Askitect Lab — 실제 Claude CLI + RDF/SPARQL 웹 데모
=================================================

1. 필요한 환경

  - Python 3.10 이상
  - 설치되어 있고 로그인된 Claude Code CLI
  - 실제 Claude 모델에 접속할 수 있는 인터넷 연결

같은 터미널에서 확인하세요.

  claude --version
  claude auth status

로그인이 필요하면:

  claude auth login

CLI는 --safe-mode, --tools, --no-session-persistence를 지원해야 합니다.
이 환경에서 검증한 버전은 2.1.296입니다.

2. 설치와 실행

아래 경로는 프로젝트 루트(etnews-demo)를 기준으로 한 상대 경로입니다.
최초 한 번 가상환경을 만들고 RDFLib를 설치하세요.

  python3 -m venv 03-askitect/.venv
  03-askitect/.venv/bin/python -m pip install -r 03-askitect/requirements.txt

서버 실행:

  03-askitect/.venv/bin/python 03-askitect/server.py

브라우저 접속:

  http://localhost:8004/03-askitect/

이미 03-askitect 폴더 안에 있다면:

  .venv/bin/python server.py

서버가 실행 중인 터미널을 켜 두세요.
종료하려면 그 터미널에서 Ctrl+C를 누르세요.
실행 중이던 모델 호출도 취소됩니다.

다른 포트나 모델을 지정하는 예:

  03-askitect/.venv/bin/python 03-askitect/server.py --port 8005 --model sonnet

위 경우 접속 주소는 http://localhost:8005/03-askitect/ 입니다.
각 Claude 호출의 기본 제한 시간은 180초이며 --timeout 300처럼 조정합니다.

python3 -m http.server나 index.html 파일 직접 열기로는 실제 CLI 호출을
할 수 없습니다. 반드시 이 폴더의 server.py를 실행하세요.
웹 서버는 127.0.0.1에서만 동작하는 로컬 데모 서버입니다.

3. 기본 시연: 누락 재질의 → 위임 승인권자

  (1) 기본 요청 '마케팅팀에서 4,000만 원짜리 집행 건을 올렸습니다.'를
      그대로 두고 '실제 Claude로 실행'을 누릅니다.
  (2) Claude가 부서=Marketing, 금액=40000000, 목적=null을 추출합니다.
      모델 출력은 실제 응답이므로 결과가 다르면 실제 추출값을 확인하세요.
  (3) 추출값을 RDF에 넣고 원본 Q_MISSING SPARQL을 실행합니다.
  (4) 목적이 없으면 Claude가 실제로 재질의 문장을 작성합니다.
      화면에 나타난 입력란에 '신제품 출시 마케팅 캠페인' 등의 목적을
      직접 입력하고 '정보를 채우고 검증 계속'을 누르세요.
  (5) 입력값을 그래프에 적재한 뒤 누락 검사를 다시 실행합니다.
  (6) Q_APPROVER가 40000000 > 30000000 조건과 위임 관계를 검증합니다.
      Director → DelegatedTeamLead 경로에 따라 승인권자를 확정합니다.
  (7) Claude가 이 확정 근거를 받아 실제 최종 답변을 한 문장으로 씁니다.

목적만 누락된 기본 예제는 보통 실제 Claude CLI를 세 번 호출합니다.
  자연어 추출 1회 / 목적 재질의 1회 / 최종 문장 1회
누락 항목이 더 많으면 재질의 호출 수도 늘어납니다.
목적을 처음부터 명시하면 재질의를 건너뛸 수 있습니다.

예시 응답이나 자동 규칙 폴백으로 실제 모델을 흉내 내지 않습니다.
CLI 실패, 로그인 오류, JSON 추출 실패는 오류로 표시합니다.
최종 문장 생성에 실패해도 이미 검증된 SPARQL 결정과 근거는 보존합니다.

4. 비교 시연

  '1,200만 원 · 원본':
    원본 Python의 기본 요청입니다. 정책 임계값은 3,000만 원이므로
    목적을 보완한 후에도 초과금액 승인 규칙은 적용되지 않습니다.
    3,000만 원과 정확히 같아도 > 조건을 만족하지 않습니다.

  '인사팀 · 규칙 없음':
    HR 부서에는 규칙이 없습니다. 판단 보류로 표시합니다.
    조회 결과가 없다는 이유로 승인 불필요라고 단정하지 않습니다.

  '본부장 → 위임 팀장 관계 적용' 체크 해제:
    이번 실행 그래프에서 위임 트리플만 제거합니다.
    4,000만 원 요청의 승인권자는 Director가 됩니다.
    원본 askitect.ttl 파일은 변경하지 않습니다.

  모든 정보를 처음부터 포함하는 요청:
    마케팅팀에서 신제품 캠페인을 위해 4,000만 원 집행을 요청합니다.

금액이 임계값 이하이거나 규칙 자체가 없는 경우에는 원본처럼
SPARQL 결과를 표시하고 종료합니다. 이 분기에서는 최종 문장용 LLM을
추가 호출하지 않습니다. 자연어 추출과 필요한 재질의는 실제 Claude입니다.

5. 화면과 저장 자료

  - 구조화된 요청: Claude 추출값과 사용자가 입력한 보완값을 구분
  - 지식 그래프: 이번 요청과 원본 정책의 실제 RDF 관계 표시
  - 녹색 경로: SPARQL로 확정된 금액/승인/위임 근거
  - 실행 기록: 모델 호출, 그래프 적재, 질의, 사용자 입력의 진행 순서
  - 실제 Claude 호출 내역: 전송 프롬프트, 응답 원문, 모델, 세션, 소요 시간
  - 다운로드: 해당 실행의 result.json과 graph.ttl

이 폴더 기준 다음 경로에 실행 기록을 저장합니다.

  runtime/<실행 ID>/result.json
  runtime/<실행 ID>/graph.ttl

사용자 입력과 실제 모델 응답이 포함됩니다. runtime/은 Git에서 제외됩니다.
각 실행은 독립적인 그래프와 디렉토리를 사용합니다.
동시에 한 실행만 진행합니다. 재질의 입력을 기다리는 실행도 포함합니다.
'취소'로 모델 호출 또는 입력 대기를 끝낼 수 있습니다.
새로고침은 현재 서버의 마지막 실행에 다시 연결하며 재호출하지 않습니다.
서버를 재시작하면 웹 목록은 초기화되지만 저장된 파일은 남습니다.

6. 원본과의 관계

이 README.txt가 있는 폴더 기준 원본 경로:
  ../../etnews/2026-08-19/demo/ex05_askitect/

askitect.py, askitect.ttl, requirements.txt는 원본을 복사했습니다.
웹 엔진은 원본 commit_request(), find_missing(), decide_approver(),
fill_value()와 원본의 Q_MISSING, Q_APPROVER를 사용합니다.

웹 버전에서 보강한 점:
  - 실제 CLI 실패 시 조용히 폴백하지 않고 오류 표시
  - 추출 JSON의 필드/타입 검증과 보완 입력값 검증
  - 사용자 입력을 기다린 뒤 같은 그래프에서 검증 재개
  - 재질의 후 마지막 입력도 다시 검증
  - 실제 CLI 도구/MCP/사용자 커스터마이징 비활성화, 독립 세션 사용

원본 TTL의 Request_001은 정적 예제입니다. 웹에서는 매 실행마다 새 그래프의
Request_web을 대상으로 질의하며 Request_001의 값을 빌려오지 않습니다.
그래프 화면에서는 정책과 현재 요청만 표시합니다. 전체 TTL은 다운로드로 봅니다.

rdfs:domain을 필수 속성으로 해석하는 것은 이 데모의 검증 규약입니다.
RDF 자체는 rdfs:domain만으로 누락을 오류로 처리하지 않습니다.
이 데모는 승인권자 안내를 위한 것이며 실제 결재를 제출하거나 승인하지 않습니다.
LLM의 마지막 문장과 별개로 '규칙 판단' 카드가 SPARQL 결정의 원본입니다.
계정의 실제 Claude 사용량/요금 한도가 적용됩니다.

7. 검증

프로젝트 루트에서:

  03-askitect/.venv/bin/python -B -m unittest discover -s 03-askitect/tests -p 'test_*.py' -v

자동 테스트의 모델은 테스트 대역이며 모델 비용을 발생시키지 않습니다.
RDF/SPARQL 처리는 테스트에서도 실제 RDFLib로 실행합니다.
실제 CLI 연결은 서버를 실행한 뒤 웹에서 요청과 재질의 입력까지 진행해 확인합니다.

8. 문제 해결

  ModuleNotFoundError: rdflib
    가상환경의 Python으로 실행했는지, requirements 설치를 했는지 확인하세요.

  서버 연결 오류
    정적 웹 서버가 아니라 server.py인지, 포트와 접속 주소가 맞는지 확인하세요.

  CLI/로그인/모델 오류
    같은 터미널에서 claude --version과 claude auth status를 확인하세요.
    화면에 표시된 실제 오류를 해결한 뒤 새로 실행하세요.

  재질의 금액 입력 오류
    금액 입력란에는 40000000 또는 40,000,000처럼 원 단위 숫자를 입력하세요.
    4천만원 등 자연어 표현은 최초 요청에 사용하고, 보완 입력에는 쓰지 않습니다.
