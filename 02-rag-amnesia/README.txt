RAG Amnesia Lab — 실제 Claude CLI 웹 데모
=======================================

1. 준비

  - Python 3.10 이상
  - 설치되어 있고 로그인된 Claude Code CLI
  - Claude 서버에 접속할 수 있는 인터넷 연결

서버를 실행할 터미널에서 확인하세요.

  claude --version
  claude auth status

로그인이 필요하면:

  claude auth login

검증한 CLI 버전: 2.1.296.
--safe-mode, --tools, --no-session-persistence 옵션을 지원해야 합니다.
해당 옵션을 지원하지 않는 버전은 Claude Code를 업데이트하세요.
웹 서버용 Python 패키지는 추가로 설치하지 않아도 됩니다.

2. 실행해서 웹으로 보기

프로젝트 루트(etnews-demo)에서:

  python3 02-rag-amnesia/server.py --port 8003

브라우저 접속:

  http://localhost:8003/02-rag-amnesia/

이미 02-rag-amnesia 폴더 안에 있다면:

  python3 server.py --port 8003

터미널을 켜 둔 상태로 웹의 '실제 Claude로 실행' 버튼을 누르세요.
서버 종료는 터미널에서 Ctrl+C를 누릅니다.

주의: 이전의 python3 -m http.server 명령으로는 Claude를 호출할 수 없습니다.
반드시 server.py를 실행하세요. index.html을 파일로 직접 여는 방식도
실제 모델 실행을 지원하지 않으며, 화면에 서버 연결 오류를 표시합니다.
기존 정적 서버가 실행 중이라면 종료하거나 다른 포트를 사용하세요.
8003번 포트가 사용 중이면 --port 8004로 변경하고 접속 주소도 바꾸세요.

3. 실제 실행 흐름

실행 버튼을 한 번 누르면 실제 Claude CLI를 총 네 번 호출합니다.

  1) 일반 RAG 1턴: 어제 일기 검색 → Claude가 기준 정리
  2) 메모리 RAG 1턴: 같은 검색 문맥 → Claude가 기준 정리
     이 실제 응답을 실행별 criteria.md 파일에 저장
  3) 일반 RAG 2턴: 오늘 일기 검색 → 이전 답변 없이 Claude 호출
  4) 메모리 RAG 2턴: 오늘 일기 검색 + 저장 파일을 다시 읽어 주입 → Claude 호출

각 호출은 독립적인 claude -p 프로세스입니다. --resume/--continue를 사용하지
않습니다. 도구, MCP, 프로젝트 지침, 사용자 커스터마이징, CLI 세션 저장을
비활성화하여 원본의 시스템 프롬프트와 검색 문맥으로 응답하도록 구성했습니다.
계정 인증은 설치된 Claude CLI의 기존 로그인을 사용합니다.
실제 모델 사용량과 요금/한도는 해당 Claude 계정의 설정에 따릅니다.

4. 웹 화면에서 확인할 것

  - 실행 상태: 대기 / 생성 중 / 완료 / 실패 / 취소, 각 호출 소요 시간
  - 1단계: 두 모드에서 각각 생성된 실제 1턴 답변
  - 2단계: 실제 파일에 저장한 메모리와 일반 RAG의 이전 답변 미전달
  - 3단계: 검색 문서와 실제 주입된 파일 내용
  - 4단계: 실제 2턴 답변 및 키워드 기준 언급 수
  - '두 모드에 전달할 프롬프트 비교': 호출에 사용한 실제 프롬프트
  - 'criteria.md 다운로드': 이번 실행에서 실제 저장한 파일 내용

실행 완료 시 답변 비교 화면으로 이동합니다. 단계 버튼으로 원하는 과정을
다시 볼 수 있습니다. '다음 단계'는 보기만 바꾸며 모델 호출을 추가하지 않습니다.
'실행 취소'는 진행 중인 CLI 프로세스를 종료하고 완료된 응답은 남깁니다.

'검색 문서 수'를 2개로 바꾸면 현재 표시 결과가 초기화됩니다.
새로운 설정의 결과를 보려면 '실제 Claude로 실행'을 다시 누르세요.
예시 답변으로 대체하지 않으며, 0/3 또는 3/3 같은 결과를 미리 정하지 않습니다.
모델이 어떤 표현으로 답하는지에 따라 매번 다른 결과가 나올 수 있습니다.

페이지 새로고침은 같은 서버의 마지막 실행을 다시 표시하며 추가 호출하지
않습니다. 서버를 재시작하면 웹 실행 목록은 초기화되지만 저장 파일은 남습니다.
↺는 화면의 선택과 결과만 초기화합니다. 저장된 파일을 삭제하지 않습니다.

5. 저장 파일과 모델 설정

이 폴더 기준:

  memory/runs/<실행 ID>/criteria.md
  memory/runs/<실행 ID>/result.json

criteria.md에는 메모리 모드 1턴의 실제 응답을 저장합니다.
result.json에는 실행 상태, 검색 점수, 전송 프롬프트, 실제 답변,
기준 검사 결과, 호출별 소요 시간, CLI가 제공한 세션/사용량 정보를 저장합니다.
새 실행마다 별도 폴더를 사용하므로 이전 실행의 메모리를 덮어쓰지 않습니다.
메모리/결과 파일은 .gitignore에 포함되어 있습니다.

기본 요청 모델은 원본과 같은 claude-sonnet-4-6입니다.
다른 모델을 지정하려면:

  python3 02-rag-amnesia/server.py --port 8003 --model sonnet

각 호출의 기본 제한 시간은 180초입니다. 필요하면 늘릴 수 있습니다.

  python3 02-rag-amnesia/server.py --port 8003 --timeout 300

로컬 데모 서버는 127.0.0.1에만 바인딩됩니다.
원격 공개 호스팅용 서버가 아닙니다.

6. 오류가 날 때

  서버 연결 오류:
    정적 http.server 대신 server.py를 실행했는지 접속 주소를 확인하세요.

  claude CLI를 찾을 수 없음:
    같은 터미널에서 claude --version이 동작하는지 확인하세요.

  로그인/사용량/모델 접근 오류:
    claude auth status로 상태를 확인하고 화면의 실제 오류를 확인하세요.
    로그인이나 모델 설정을 고친 뒤 다시 실행하세요.

  시간 초과:
    네트워크와 CLI 상태를 확인하고 필요하면 --timeout을 늘리세요.

실패해도 가짜 답변이나 임의 점수로 대체하지 않습니다.
앞선 호출이 성공했다면 그 실제 응답은 유지합니다.

7. 계산과 평가의 의미

검색은 원본 rag_amnesia.py의 TfidfRetriever를 서버에서 직접 사용합니다.
코퍼스와 두 질문, 시스템 프롬프트, build_prompt(), score_criteria()도 원본을
사용합니다. 브라우저의 검색 미리보기는 같은 TF-IDF 계산을 JavaScript로 옮겼습니다.

기준 언급 수는 단순한 부분 문자열 검사입니다. 부정문이나 확인 질문도
키워드가 포함되면 언급으로 셉니다. 생활 기준 달성률이나 답변의 정확도는 아닙니다.
오늘 일기에 걷기 시간과 커피 지출액이 없으므로 기준 준수 여부를 단정할 수 없습니다.

이 실험은 대화 이력을 전달하지 않는 일반 RAG를 가정합니다.
모든 RAG 시스템이 과거 대화를 잊는다는 의미는 아닙니다.

8. 원본과 검증

이 README.txt 폴더 기준 원본 경로:
  ../../etnews/2026-08-19/demo/rag-amnesia/

원본 CLI를 검색 전용으로 실행하려면 프로젝트 루트에서:

  python3 02-rag-amnesia/rag_amnesia.py --dry-run

서버 테스트 (실제 모델 요금이 발생하지 않는 테스트 대역 사용):

  python3 -B -m unittest discover -s 02-rag-amnesia/tests -p 'test_*.py' -v

JavaScript 검색과 원본 Python의 일치 확인 (Node.js 18 이상 필요):

  node --test 02-rag-amnesia/tests/rag.test.cjs

실제 Claude 연결은 server.py를 띄운 뒤 웹에서 실행해 확인합니다.
Node.js는 웹 시연에 필요하지 않습니다.
